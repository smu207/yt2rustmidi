# yt2midi 웹

노래 파일을 브라우저 안에서 **보컬 · 드럼 · 베이스 · 기타 악기**(6트랙 모드는 **기타 · 피아노**까지)로 분리하고, 각각을 **MIDI**로 바꾼 뒤, 잘못 잡힌 잡음 음표를 **피아노 롤에서 직접 고칠 수 있는** 웹페이지입니다.

서버 없이 동작합니다. 모든 계산은 방문자의 브라우저 안에서 이루어지고, 파일은 어디에도 올라가지 않습니다. 그래서 GitHub Pages 같은 무료 정적 호스팅에 그대로 올릴 수 있습니다.

## 들어 있는 것

| 파일 | 역할 |
|---|---|
| `index.html` | 페이지 전체 (변환 · 편집 · 솔로 편곡) |
| `arranger.js` | 합주곡을 악기 하나용 솔로곡으로 바꾸는 편곡기 |
| `app.bundle.js` | 변환 엔진 (`src/pipeline.js`를 빌드한 결과) |
| `model/basic-pitch/` | 음표 변환 모델 (약 0.9MB) |
| `src/pipeline.js` | 변환 엔진 소스 코드 |
| `python/` | 유튜브 링크를 바로 넣어 쓰는 로컬용 파이썬 버전 |

분리 모델은 저장소에 넣지 않고, 첫 실행 때 Hugging Face에서 받아 브라우저에 저장해 둡니다. 4트랙은 약 170MB, 6트랙은 약 136MB입니다.

## 동작 방식

1. **오디오 읽기**: 파일을 44.1kHz 스테레오로 바꿉니다.
2. **악기 분리**: [Demucs](https://github.com/facebookresearch/demucs)를 ONNX Runtime Web으로 실행합니다. GPU(WebGPU)가 있으면 GPU를, 없으면 CPU를 씁니다.
   - **4트랙**(기본): HTDemucs, [demucs-web](https://github.com/timcsy/demucs-web) 사용
   - **6트랙**(실험적): HTDemucs 6s의 [ONNX 변환본](https://huggingface.co/adowu/htdemucs-6s-onnx). 기타와 피아노를 따로 나눕니다. 이 브라우저에서 실패하면 자동으로 4트랙으로 바꿔 진행합니다.
3. **음표 변환**:
   - 보컬·베이스·기타 악기는 Spotify [Basic Pitch](https://github.com/spotify/basic-pitch-ts)로 변환합니다.
   - 보컬과 베이스는 한 번에 한 음만 남도록 정리합니다.
4. **드럼**: 킥 · 스네어 · 하이햇 대역별로 타격 순간을 찾습니다.
5. **템포**: 자동으로 추정하고, 직접 입력할 수도 있습니다.
6. **결과**:
   - 악기별 WAV, 악기별 MIDI, 전체 MIDI를 저장할 수 있습니다.
   - 결과는 편집기에 자동으로 열립니다.

## ⚠️ 유튜브 링크에 대해

웹페이지는 브라우저 보안 정책(CORS) 때문에 **유튜브에서 소리를 직접 받아올 수 없습니다**. GitHub Pages에는 대신 받아 줄 서버도 없습니다.

그래서 페이지에 유튜브 링크를 넣으면 **내 컴퓨터에서 실행할 다운로드 명령**을 만들어 줍니다.

```bash
pip install yt-dlp          # 처음 한 번 (ffmpeg도 필요)
yt-dlp -x --audio-format mp3 -o "%(title)s.%(ext)s" "유튜브 링크"
```

받은 mp3 파일을 페이지에 끌어다 놓으면 됩니다. 링크 하나로 끝까지 자동으로 하고 싶다면 `python/yt2midi.py`를 쓰세요.

권리가 있는 곡이나 개인 학습 용도로만 사용하세요.

## 러스트(Rust) 악기용 솔로 편곡 (3번 탭)

러스트는 MIDI 파일의 모든 트랙을 손에 든 악기 하나로 연주합니다. 그래서 합주 MIDI를 그대로 넣으면 소리가 뒤엉킵니다. **솔로 편곡**은 여러 트랙을 한 악기가 칠 수 있는 한 트랙으로 다시 짜 줍니다.

**만드는 순서**
1. **멜로디**: "멜로디" 역할 트랙에서 가장 높은 음 한 줄을 뽑습니다. 아주 짧거나 약한 잡음 음은 뺍니다.
2. **코드 찾기**: "반주"와 "베이스" 트랙의 음을 1박, 2박 또는 1마디마다 모아 장·단3화음을 찾습니다.
3. **배치**: 악기 음역 안에서 위쪽에 멜로디, 맨 아래에 베이스, 그 사이에 코드를 놓습니다.
   - 코드는 앞 코드와 가까운 자리를 골라 덜 튀게 합니다.
   - 반주가 멜로디보다 높아지지 않게 합니다.
4. **반주 방식**: 블록 코드, 쿵짝, 아르페지오, 멜로디만 중에서 고릅니다.
5. **악기 한계 맞추기**:
   - 동시에 내는 음 수를 넘지 않게 정리합니다. 멜로디가 항상 우선입니다.
   - 음역을 벗어나는 음은 옥타브를 옮겨 맞춥니다.
   - 필요하면 곡 전체를 옥타브 단위로 옮깁니다. 반음 단위 조옮김도 고를 수 있습니다.

**쓰는 법**
1. 편집기에서 잡음을 먼저 정리합니다.
2. 3번 탭에서 트랙 역할을 확인하고, 악기와 편곡 방식을 고른 뒤 **솔로곡 만들기**를 누릅니다.
3. **편집기에서 듣고 다듬기**를 누르면 "Solo (편곡)" 트랙이 솔로로 켜진 채 열립니다. 들어 보고 손봅니다.
4. **솔로 MIDI 저장**으로 저장합니다. 솔로 트랙 하나만 든 파일이 만들어집니다.

**게임에서 재생하기**
1. Steam에서 Rust → 관리 → 로컬 파일 보기를 엽니다.
2. `Rust.exe` 옆에 `instruments` 폴더를 만들고 파일을 넣습니다.
3. 게임에서 악기를 들고 F1 콘솔에 `instruments.playrecording 파일이름`을 입력합니다. 확장자 `.mid`는 빼고 적습니다.
4. 파일 이름은 영문·숫자·밑줄로 하는 것이 안전합니다.

**음역에 대해**
- 러스트 악기별 정확한 음역과 동시음 수는 공식 자료에 없습니다. 페이지의 악기 프리셋은 **추정값**입니다.
- **음역 테스트 MIDI 저장**으로 받은 `range_test.mid`(C1~C8 반음계, C는 길게)를 게임에서 재생해 보세요.
- 실제로 소리 나는 가장 낮은·높은 음을 확인한 뒤 최저·최고 음 번호를 맞추면 됩니다.

# GitHub Pages로 올리기

## 방법 A. 웹사이트에서 끌어다 놓기 (git 몰라도 됨)

1. [github.com](https://github.com)에 로그인하고 오른쪽 위 **+ → New repository**를 누릅니다.
2. 저장소 이름을 적습니다 (예: `yt2midi-web`).
   - **Public**을 고르세요. 무료 계정에서 Pages를 쓰려면 공개 저장소여야 합니다.
   - **Create repository**를 누릅니다.
3. 새 저장소 화면에서 **uploading an existing file** 링크를 누릅니다.
4. 압축을 푼 `yt2midi-web` 폴더 **안의 내용물**을 끌어다 놓습니다.
   - 필요한 것: `index.html`, `app.bundle.js`, `arranger.js`, `model` 폴더, `.nojekyll`
   - 나머지 파일도 같이 올려도 됩니다. 단 `node_modules`는 올리지 마세요.
   - ⚠️ `index.html`이 저장소의 **맨 위(루트)**에 있어야 합니다. 폴더째 올리면 주소가 한 단계 깊어집니다.
   - `.nojekyll`처럼 점으로 시작하는 파일은 운영체제에서 숨김 파일이라 안 보일 수 있습니다. 빠져도 이 페이지는 동작합니다.
5. 아래 **Commit changes**를 누릅니다.
6. 저장소 위쪽 **Settings → (왼쪽) Pages**로 갑니다.
7. **Build and deployment**에서 다음과 같이 설정하고 **Save**를 누릅니다.
   - **Source**: `Deploy from a branch`
   - **Branch**: `main`, 폴더 `/ (root)`
8. 1~3분 기다린 뒤 새로고침하면 위쪽에 주소가 나옵니다.
   ```
   https://<내 아이디>.github.io/yt2midi-web/
   ```
   진행 상황은 저장소의 **Actions** 탭에서 볼 수 있습니다.

## 방법 B. 터미널(git)로 올리기

```bash
cd yt2midi-web
git init
git add .
git commit -m "yt2midi 웹 첫 버전"
git branch -M main
git remote add origin https://github.com/<내 아이디>/yt2midi-web.git
git push -u origin main
```

그다음 방법 A의 6~8단계(Settings → Pages)를 똑같이 하면 됩니다.

GitHub CLI가 있다면 저장소 만들기와 올리기를 한 번에 할 수도 있습니다.

```bash
gh repo create yt2midi-web --public --source=. --push
```

## 수정한 뒤 다시 올리기

- **`index.html`만 고쳤을 때**: 그 파일만 다시 올리거나 `git push` 하면 1~2분 뒤 반영됩니다.
- **`src/pipeline.js`를 고쳤을 때**: 빌드를 다시 해야 합니다. Node.js가 필요합니다.
  ```bash
  npm install
  npm run build      # app.bundle.js 와 model/basic-pitch 를 다시 만듦
  ```
- **반영이 안 보일 때**: 브라우저가 옛 파일을 기억하고 있을 수 있습니다. `Ctrl+Shift+R`로 강력 새로고침하세요.

## 올리기 전에 내 컴퓨터에서 확인하기

`index.html`을 더블클릭해서 열면 보안 정책 때문에 모델을 못 읽습니다. 작은 웹서버를 띄워서 여세요.

```bash
cd yt2midi-web
python -m http.server 8080
# 브라우저에서 http://localhost:8080 열기
```

## 사용 팁

- **브라우저**:
  - 크롬이나 엣지 최신 버전을 권장합니다.
  - WebGPU가 되면 분리가 훨씬 빠릅니다.
  - CPU로 돌리면 곡 1분당 수 분 정도 걸릴 수 있습니다.
- **메모리**:
  - 긴 곡은 메모리를 많이 씁니다.
  - 처음에는 시작·끝 시간을 지정해 30~60초로 시험해 보세요.
  - 메모리가 부족하다는 오류가 나면 1~2분씩 나눠서 변환하세요.
- **휴대폰**: 휴대폰에서는 메모리 한계로 실패할 수 있습니다. 편집기는 휴대폰에서도 동작합니다.
- **모델 저장**:
  - 분리 모델은 브라우저에 저장되므로 두 번째부터는 다운로드 없이 시작합니다.
  - 지우려면 페이지 아래 **저장된 모델 지우기**를 누르세요.
- **잡음 정리**:
  - 편집기 왼쪽 **잡음 의심 음표** 기준(짧은 음, 약한 음, 외톨이 음, 음역 밖)을 조절하세요.
  - **의심 음표 선택** → 확인 → `Delete` 순서로 정리합니다.
  - 기준은 곡마다 다르니 하나씩 바꿔 가며 들어 보세요.
- **4트랙과 6트랙 고르기**:
  - 기타나 피아노 중 하나만 나오는 곡은 4트랙으로 충분합니다.
  - 둘 다 비중 있게 나오면 6트랙을 써 보세요.
  - 피아노 분리는 품질이 고르지 않아 다른 트랙으로 소리가 새거나 잡음이 섞일 수 있습니다.
  - 6트랙 모드가 이 브라우저에서 동작하지 않으면 파이썬 버전(`python/yt2midi.py`, 기본 6트랙)을 쓰세요.
- **섞인 트랙 나누기** (편집기 왼쪽 **트랙 다듬기**):
  - **음표 고르기**: **이 음역 선택**, **가장 높은 음만**, **가장 낮은 음만** 중 하나를 쓰거나, 피아노 롤에서 드래그로 직접 고릅니다.
  - **옮기기**: **선택 → 새 트랙** 또는 **선택 → 이 트랙으로**를 누릅니다.
  - **정리**: 트랙 이름과 악기(저장할 때 쓰는 소리)를 바꿀 수 있습니다.
  - 예시: 반주 트랙에서 멜로디만 빼려면 **가장 높은 음만**을 고른 뒤 **선택 → 새 트랙**을 누릅니다.
  - 전부 되돌리기(Ctrl+Z)가 됩니다.
